# Codacy Configuration

## Files

| File | VCS | Purpose |
|------|-----|---------|
| `codacy.config.json` | **gitignored** | Auto-generated by the Codacy CLI on every analyze run (remote snapshot with org/repository metadata and the full pattern list). Never commit — the CLI overwrites it constantly. |
| `codacy.config.baseline.json` | **gitignored** | Auto-generated remote baseline (~186 KB). Contains org/repository IDs and the full baseline'd pattern list. Regenerated locally by the Codacy CLI on demand. |
| `codacy.yaml` | committed | Codacy cloud configuration — the real, stable config. |
| `cli.sh` | committed | Codacy CLI bootstrap script (used by CI Trivy step). |
| `biome.json` (repo root) | committed | Local Biome config — the CLI picks it up via `useLocalConfigurationFile`. |

## Why the generated configs are not committed

1. **Size/churn**: ~186 KB, 4897 lines each, rewritten with fresh timestamps on
   every CLI analyze run — noisy diffs, inflated repo.
2. **Metadata disclosure**: both embed `organization`, `repositoryId`, and the
   complete pattern list. The repo is public.
3. **Auto-overwrite**: the CLI replaces `codacy.config.json` with a remote
   snapshot on every run — a committed copy would immediately show as modified.
4. **No consumer needs them in VCS**: `cli.sh` and CI regenerate them locally
   before use.

## Regeneration strategy

Both files are regenerated automatically by the Codacy CLI:

```bash
# Via MCP tool (codacy_cli_analyze) or CLI directly:
./.codacy/cli.sh analyze
```

If a previous checkout still tracks `codacy.config.json`, untrack it:

```bash
git rm --cached .codacy/codacy.config.json
```

Rule of thumb: real configuration lives in `codacy.yaml` and `biome.json`.
Everything the CLI generates under `.codacy/` stays local.
